# Holistic Health Connect — Android companion app

Kotlin + Jetpack Compose app that reads authorized health records from
**Health Connect** on your Android phone and syncs them to your Holistic
Health Optimization Platform account over HTTPS.

```
watch / fitness app → Health Connect (via the writing app's sharing option) → this app → platform API → website
```

## Screens

1. **Welcome** — branding + what the app does.
2. **Health Connect permissions** — availability check + read-permission request
   (steps, heart rate, resting heart rate, sleep incl. stages, active calories,
   distance, exercise sessions, SpO2, HRV).
3. **Account pairing** — enter the server URL and the single-use pairing code
   generated by the website's Health Data section (valid 10 minutes).
4. **Sync** — status cards, Sync Now, and disconnect. Background WorkManager
   worker polls every 15 minutes (honours the website's "Sync Now") and runs a
   full sync at least every 6 hours.

## Build (Android Studio)

1. Open Android Studio → **Open** → select `android-companion/`.
2. Let Gradle sync (JDK 17 required, AGP 8.5.2 / Kotlin 2.0.20).
3. **Run** on a device or emulator (emulator: Health Connect is available on
   API 34+ images; the app talks to `http://10.0.2.2:3000` for a local dev
   server — cleartext is allowed for the emulator loopback only).

## Build from the command line

```bash
cd android-companion
gradle assembleDebug          # debug-signed, installable
gradle assembleRelease        # see signing below
```

(No Gradle wrapper JAR is committed — run `gradle wrapper --gradle-version 8.9`
once if you want the wrapper, or use the GitHub Actions workflow which installs
Gradle itself.)

## Signing a release APK

Keys are never committed. Create `android-companion/keystore.properties`
(git-ignored) next to `build.gradle.kts`:

```properties
storeFile=/absolute/path/to/holistic-release.jks
storePassword=YOUR_STORE_PASSWORD
keyAlias=holistic
keyPassword=YOUR_KEY_PASSWORD
```

Create the keystore once with:

```bash
keytool -genkeypair -v \
  -keystore holistic-release.jks \
  -alias holistic -keyalg RSA -keysize 2048 -validity 10000
```

Then `gradle assembleRelease` produces `app/build/outputs/apk/release/app-release.apk`.
Without a keystore the release build falls back to the debug key (installable,
fine for testing; use a real key for distribution).

## Distribute

The QR code on the website's Health Data page points at this site's own copy of
the APK by default: `https://<your-site>/downloads/holistic-health-companion.apk`
(`public/downloads/holistic-health-companion.apk` in the repo). Copy a fresh
build there and it is live — no environment variable needed.

Optional alternates:

1. **GitHub Releases** — run the `android-release` workflow (repo → Actions →
   android-release → Run), or push a `v*` tag. It builds and attaches the APK
   to a release.
2. **External hosting** — host the APK anywhere over HTTPS and set
   `NEXT_PUBLIC_COMPANION_APK_URL=<the https URL>` in the platform `.env`; the
   QR and Download button pick it up after a restart.

The server URL shown on the app's pairing screen can be pre-filled at build
time: `gradle assembleRelease -PserverUrl="https://<your-site>"`.

## Build notes (sandbox / CI)

- A full JDK is required — headless JREs lack `jlink`, which AGP needs
  (`JdkImageTransform ... jlink executable does not exist`). Use JDK 17.
- If Maven Central rate-limits the build network (HTTP 429), add
  `--init-script ../scripts/gradle-mirror-init.gradle` to route resolution
  through the Aliyun mirror (project files stay untouched).

## Troubleshooting

- **"Pairing failed" even though the code is correct.** The request never
  reached the server — the app's **Server URL** doesn't match the live site
  address. The URL is baked in at build time (`-PserverUrl=…`) and preview
  hosts can change after a redeploy, so it must be edited on the pairing
  screen to exactly the address the browser shows. The website's pairing card
  also prints the required URL. As of v1.1.1 the app says "Could not reach
  <url>…" for this case, and non-JSON proxy error pages are reported as
  "HTTP <code> — the server sent a non-JSON page. Check the Server URL."
  instead of a cryptic JSON parse error.
- **Permission dialog shows nothing / sync reports 0 granted permissions.**
  Health Connect only grants permissions the app declares in
  `AndroidManifest.xml` (`android.permission.health.READ_*`). All nine are
  declared there and must stay in sync with `HealthConnectManager.PERMISSIONS`
  — requesting an undeclared permission silently returns "not granted".
- **Re-granting later.** The sync home screen shows a red
  "Health Connect permissions missing" card with a grant button whenever the
  granted count is below the requested set; granting from there also kicks off
  a sync immediately.

## Watch / fitness app notes

- Enable sharing in your watch/fitness app's **Health Connect** settings
  (e.g. its *Data permissions / Data sharing* screen) so the watch data lands
  in Health Connect.
- Only measurements the writing app actually shares will appear. The platform
  shows "no records" for everything else — nothing is simulated.
- Expect: steps, heart rate, sleep (with stages where provided), active
  calories, distance, SpO2. Resting heart rate and HRV depend on the writing
  app — verify on-device after the first sync.

## Privacy

- The sync token is device-scoped and revocable from the website; only its
  SHA-256 hash is stored server-side, and it lives in encrypted preferences
  locally.
- Disconnecting on the website revokes the token and deletes the readings that
  arrived through Health Connect sync.
